# ADR-002: DuckDB star schema over the raw PIX zone

- Status: accepted
- Date: 2026-11-24

## Context

v0.1 lands three monthly Olinda extracts as Parquet: `EstatisticasTransacoesPix`, `TransacoesPixPorMunicipio`, and `ChavesPix`, under `raw/bcb/<entity>/ano_mes=YYYYMM/part.parquet`. v0.2 has to make that zone queryable. The later slices are already chosen: FastAPI and CDC (v0.3), Terraform with Glue partition projection and Athena (v0.4), dbt (v0.5), Airflow (v0.6), Metabase (v1.0). This slice should not invent a warehouse those slices have to throw away.

The spike (`docs/spike-bcb.md`, 2026-11-24) fixes the grain. Every series used here is monthly (`AnoMes`, or a key snapshot dated the last day of the month). There is no per-bank payment volume: the transaction resources have no ISPB, and `ChavesPix` is a stock of keys. `NATUREZA` has nine codes. Each municipality month has one `N/D` row whose IBGE fields are null. `EstatisticasFraudesPix` is one national row and, on that date, only through `202609`. It is not in the raw zone.

Postgres is in the compose file for the payments app. It is not the analytical store.

## Decision

Model the raw zone as a star schema in DuckDB, in plain SQL, one model per file.

- The runner (`python -m transform build`, `make model`) creates `raw` views with `read_parquet`. Local files use the directory that mirrors the ingestion layout. S3, including LocalStack, uses the httpfs extension: path-style HTTP when `AWS_ENDPOINT_URL` is set, and the default virtual-hosted client when it is empty. Model SQL does not mention Parquet or S3. v0.4 replaces the `raw` views with Glue tables and keeps the SELECTs.
- Layers, in build order: `seeds`, `staging`, `intermediate`, `marts`. Seeds, staging, and intermediate are views. Marts are tables in `data/pix.duckdb` (override with `PIX_DUCKDB_PATH`), so a query does not depend on the raw files staying put.
- Staging quotes the physical Olinda names and emits snake_case columns at `DECIMAL(38, 8)`, the scale the raw writer uses. Intermediate applies the business rules: the `N/D` municipality becomes `municipio_ibge` 0 with the name `Não informado`, `ano_mes` is derived from the key snapshot date, and ISPB is left-padded to 8 characters. Marts are the dimensions and facts.
- SQL stays in the subset DuckDB shares with Athena and Trino: no `read_parquet`, `QUALIFY`, `GROUP BY ALL`, or DuckDB date helpers inside model files. A test scans the SQL for those tokens. v0.5 dbt ports the files; the schema-qualified names (`staging.`, `marts.`) are the seam that becomes `ref()`.

### Grain

| Model | Grain | Measures |
| --- | --- | --- |
| `fct_transacoes_mensal` | month × payer and receiver person type, region, and age band × initiation form × natureza × finalidade | `valor`, `quantidade`. They add across the grain to the national month. Payer and receiver are columns of the same row. |
| `fct_transacoes_municipio` | month × municipality, including `municipio_ibge` 0 | value and count sent (`valor_enviado`) and received (`valor_recebido`), plus distinct-person counts. Do not add the sent and received sides. Person counts are not a national distinct total. |
| `fct_chaves_pix` | snapshot month × ISPB × user nature (PF/PJ) × key type | `quantidade_chaves`, a stock. Not payment volume. |

`dim_tempo` is one row per `AnoMes` that appears in any entity. `data_inicio` and `data_fim` are the first and last day of that month, including 29 February. There is no day grain.

`dim_municipio` carries the IBGE municipality code, the UF code and sigla, and the macro-region. UF attributes are denormalized onto the municipality (no `dim_uf` snowflake). The sigla comes from a seed of the 27 IBGE state codes. The `N/D` row is kept as one member, `municipio_ibge` 0, name `Não informado`. IBGE does not assign 0. A raw null IBGE code with no dimension row fails a data-quality check, so the bucket cannot disappear quietly.

`dim_natureza` maps the nine codes. P2P, P2B, B2P, and B2B follow the footnote in the BCB Relatório Anual do SPI 2025. P2G is named in the Relatório de Gestão do Pix 2023-2025. G2P, B2G, G2B, and G2G use that same payer-to-receiver convention (P pessoa física, B pessoa jurídica, G governo) and are flagged `publicado = false`, because the Gestão report groups them as Governo and does not gloss each code. A code that shows up in the extract and is not in the seed is kept, with the raw code as the label.

The other dimensions are the columns the extracts actually contain: initiation form, finalidade, age band, person type, macro-region, key type, and institution (ISPB). Initiation-form labels come from the Manual de Padrões para Iniciação do Pix, version 2.10.0, section 3.2, plus the APDN domain recorded by the Fórum Pix. `APES` is in the extract; its "static approximation" label is inferred from the QRES/QRDN pair and is flagged `publicado = false`. `dim_instituicao` is type 1: name and segment come from the latest snapshot. The fact still has one row per month.

`EstatisticasFraudesPix`, `CnaePorteRecebedor`, and `PixUsuariosCadastradosDICT` are not modeled. They are not ingested.

### Data quality

`transform/sql/checks` holds one SELECT per rule. A row in the result is a violation. The rules are uniqueness of each fact grain and of each dimension key, not-null keys, referential integrity from facts to dimensions, non-negative amounts and counts, the presence of the `Não informado` municipality when a null IBGE code was published, and a single name per ISPB on the latest snapshot. `make dq` runs them against the DuckDB file. pytest runs the same function on a warehouse built from small Parquet fixtures, so CI does not call Olinda or S3.

## Alternatives considered

- Start with dbt. v0.5 is that port. A dbt project in v0.2 would add a tool before the SQL and the grain decisions exist. The files are already one model per layer, which is the port.
- Load the raw zone into the compose Postgres. That database is the OLTP source for v0.3. The analytical copy would then have to be unloaded again for Athena. DuckDB reads the Parquet in place.
- Use DuckDB-only syntax (`QUALIFY`, `GROUP BY ALL`, `read_parquet` inside the models). It is shorter, and it would make the Athena and dbt ports a rewrite. The runner is the only DuckDB-specific layer.
- Drop the `N/D` municipality as incomplete. It is a published bucket, one row per month, and dropping it changes every municipal total. It is a dimension member.
- Model fraud from the spike notes. The raw zone does not contain it. A fact with no source would be fiction.

## Consequences

- `make model` reads `PIX_RAW_ROOT` (default `data/raw`) unless `PIX_RAW_SOURCE=s3`. After `make ingest` the files are in LocalStack, so the matching command is `PIX_RAW_SOURCE=s3 make model`. The first S3 build installs the httpfs extension, which needs a download from DuckDB's extension repository.
- Example questions live in `docs/queries`: monthly volume, top UFs and municipalities by value received (not per capita; there is no population), and the key-type mix on the latest snapshot.
- A new Olinda code flows into the dimension with `publicado = false` instead of failing the build. The data-quality check fails if a fact key has no dimension row, which happens only if a dimension is edited by hand.
- `dim_instituicao` shows the current name. A rename is visible on the next snapshot and is not historical.
- v0.4 can keep these SELECTs under Athena. v0.5 replaces schema names with `ref()` and moves the checks to dbt tests. The grain does not change.
