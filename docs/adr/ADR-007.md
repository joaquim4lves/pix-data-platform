# ADR-007: Metabase on local DuckDB, definitions in git

- Status: accepted
- Date: 2026-11-25

## Context

v1.0 is the dashboard slice. The audience is a recruiter running a laptop, not an AWS account. ADR-004 drew Metabase on the laptop with a dotted line to Athena. That Athena workgroup has never been applied. The marts that exist today are DuckDB tables in `data/pix.duckdb`.

Metabase does not ship a DuckDB driver. The process that embeds DuckDB has to load a native library. The official Metabase image is Alpine (musl). The DuckDB JDBC build is glibc, and it fails there with `libstdc++.so.6` and then `Could not initialize class org.duckdb.DuckDBNative`. MotherDuck maintains the driver and publishes a Debian image that already contains the jar.

The driver release `1.5.6.0` (20 October 2026) is built for Metabase 0.63 and embeds DuckDB 1.5.6. A file written by DuckDB 2.x cannot be opened by 1.5.6. The Python package is therefore capped below 1.6.

Dashboard clicks are not a reproducible artifact. The collection has to come back from a clean clone.

## Decision

Metabase runs only in Docker, compose profile `metabase`. It is not in Terraform.

- Image `ghcr.io/motherduckdb/metabase-duckdb:0.63.17-duckdb1.5.6.0`. That tag is Metabase 0.63.17 plus MotherDuck driver 1.5.6.0. `latest` is not used.
- The database file is `/data/pix.duckdb`, mounted from `./data`. The connection is read-only when the driver accepts it. Metabase does not migrate the warehouse.
- `duckdb>=1.5.6,<1.6` is the writer. dbt-duckdb 1.11 runs on 1.5.6.
- Definitions live in `dashboards/metabase/`: `collection.json` and one SQL file per question. `make metabase-provision` loads them through the Metabase API. A second run replaces the collection.
- The seeded extract is `data/demo-raw`, shaped like the Olinda contracts, built as of 2026-11-25. It is not a live download. `make ingest` still loads only the three v0.1 entities.
- Dashboard marts are dbt models on top of the existing facts where those facts already exist (`fct_pix_transactions`, `fct_pix_municipality`, `fct_pix_keys_stock`) and new staging for MED, CNAE and DICT users. They are not in `transform/sql` and not in `transform/athena/views.sql`. The parity test allows that list and still compares every older model.
- `is_complete_month` uses an as-of date. Empty `pix_as_of_date` means the clock minus 3 hours, which is America/Sao_Paulo with no daylight saving since 2019. Provision sets `2026-11-25` so the seeded story does not move when the calendar does.
- CI validates the definition files and runs the dbt tests. A smoke job boots the image and runs the provisioner. It does not apply Terraform.

## Alternatives considered

- The official `metabase/metabase` image plus a downloaded jar. The Alpine image cannot load this driver. MotherDuck documents that and ships the Debian image for that reason.
- MotherDuck cloud (`md:`). The portfolio would then need an account and a token. A local file does not.
- Point Metabase at Athena. That is the dotted line in the architecture diagram. There is no applied workgroup to point at, and CI has no AWS account.
- Store the collection as a Metabase serialization YAML export. The API provisioner is smaller, the SQL stays readable, and the same files are what CI checks.
- Add MED, CNAE and DICT users to `make ingest` in this slice. `PixUsuariosCadastradosDICT` is an entity set, not a function import, and the client would need a second path. The dashboards are specified to come up from seeded data. The contracts are in `ingestion/bcb/entities.py` so the sample writer and the dbt sentinel share one schema. They are not in `ENTITY_ORDER`.

## Consequences

- `make metabase-up && make metabase-provision` is the demo. The UI is `http://localhost:3000`, user `pix@example.com`, password `PixLocal-1a`. Those are local demo credentials.
- Rebuilding the DuckDB file while Metabase has it open fails. Stop the container, or leave the file in place. `METABASE_REBUILD=1` rewrites it and expects the file to be free.
- `make dbt-build` against a raw zone that does not contain the seeded entities replaces the MED, CNAE and DICT facts with empty tables. Restore them with `METABASE_REBUILD=1 make metabase-provision` while Metabase is stopped.
- A DuckDB release 1.6 or newer will refuse to open in this Metabase image until the driver tag moves. The pin is the guard.
- The Athena edge in the diagram is still the designed AWS path. It is labeled as not applied.
