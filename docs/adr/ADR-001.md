# ADR-001: Local-first raw zone for PIX open data

- Status: accepted
- Date: 2026-11-24

## Context

v0.1 has to ingest public PIX statistics from Banco Central do Brasil and land them somewhere a later warehouse can read. The platform will eventually run on AWS (Terraform in v0.4: S3, and the rest of the account). This release has no AWS account, and it should still be runnable from a laptop with one command.

The source is the Olinda service `Pix_DadosAbertos` v1. A spike against the live API (see `docs/spike-bcb.md`) showed that the path parameter is a lower bound, `$skip` currently returns HTTP 500, and `TransacoesPixPorMunicipio` publishes the calendar month before it closes. Those facts constrain the client and the checkpoint. They do not require a real AWS account to exercise.

Postgres is part of the compose file because v0.3 adds a payments app and logical replication. v0.1 does not write to it.

## Decision

Store the raw zone as Parquet on S3, and point the AWS SDK at LocalStack in development.

- One bucket, configured by `S3_BUCKET`. `AWS_ENDPOINT_URL` selects the endpoint. A non-empty value uses path-style addressing, which LocalStack requires. An empty value is real S3 and the default virtual-hosted client. v0.4 changes the endpoint and the credentials, not the writer.
- Partitions are `raw/bcb/<entity>/ano_mes=YYYYMM/part.parquet`. `<entity>` is the function-import name (`EstatisticasTransacoesPix`, `TransacoesPixPorMunicipio`, `ChavesPix`), which is the resource that actually responds. The underscore entity sets in `$metadata` return HTTP 500 and are not used.
- A run deletes the partition prefix and writes the file again. Idempotency is "the same rows, one object", not an append.
- The watermark is a small JSON object at `raw/bcb/_state/watermarks.json`, one `ano_mes` per entity. It advances only to a closed month that this run wrote, and it never moves backward. The open month is the calendar month in America/Sao_Paulo. That month may be written and is reprocessed inside the lookback window.
- The default run reprocesses the last 3 months because BCB revises published months. A watermark that has fallen behind the window is caught up. Loading history is an explicit backfill (`--start`, `--end`).
- Rows are checked with a Pydantic model (`extra=forbid`) before any raw object is written. A broken payload goes to `quarantine/<entity>/ano_mes=YYYYMM/` as the original response body, that entity fails, and its watermark is left unchanged.
- The Olinda client retries HTTP 429/500/502/503/504 and transport errors with exponential backoff. The read timeout is 120 seconds. Pagination uses `$top` and `$skip`. If `$skip` keeps returning the 500 envelope the live service returns today, the client slices the month by `NATUREZA` or `TipoChave` instead of writing a truncated page. A month that still does not fit fails the entity.
- Postgres 16 runs beside LocalStack so the compose file is the local platform, not only the loader. Ingestion does not open a SQL connection in v0.1.

## Alternatives considered

- Call the underscore entity sets and filter them. They answer HTTP 500 with `/*{"codigo":500,"mensagem":"Erro desconhecido"}*/`. The function imports are the working interface, with `$filter` on top of the path argument.
- Trust the path argument as the month. On 2026-11-24, `EstatisticasTransacoesPix(Database='202609')` without `$filter` returned both 202609 and 202610 in the first 30 rows. `Database='202611'` plus `AnoMes eq 202610` returned nothing. The path value is a lower bound.
- Use `$skip` as the only pager. `$skip` returned HTTP 500 on the function imports and on `PixUsuariosCadastradosDICT`, and responses carried no `@odata.nextLink`. `$count` returned HTTP 403. The client still implements `$skip` for when it works, and it refuses to treat a full page as a complete month.
- Land real S3 in v0.1. That needs an account, IAM, and Terraform, which is the v0.4 slice. LocalStack keeps the same `boto3` calls.
- Use a table format (Iceberg, Delta) for the raw zone. Partition overwrite is enough for a monthly public extract that is rewritten in full. A table format can wait until a consumer needs snapshots or schema evolution across many writers.

## Consequences

- `make up && make ingest` needs Docker and outbound HTTPS to `olinda.bcb.gov.br`. It does not need AWS credentials beyond the LocalStack dummy keys.
- Switching to real S3 is an environment change: clear `AWS_ENDPOINT_URL`, set real credentials, and keep the bucket name. The partition layout does not change.
- The watermark can sit on an older month than the newest object in the bucket when the newest object is the open month. Consumers that want "latest closed month" should read the state file, not `max(ano_mes)`.
- A contract change in Olinda fails the entity and leaves a body in quarantine. That is intentional. The fix is a contract update, not a silent field drop.
- CI does not start LocalStack. The integration test skips. `make test` on a machine where `make up` has run executes it.
- v0.4 keeps this switch and adds one spelling. Lambda rejects an empty environment value, so `AWS_ENDPOINT_URL=aws` means the same thing as an empty value: real AWS, virtual-hosted S3. See [ADR-004](ADR-004.md).
