# ADR-008: Agentic development setup

- Status: accepted
- Date: 2026-11-26

## Context

This repository is a public portfolio. Reviewers, and the coding agents that prepare slices, need the same commands, domain rules, and refusals a senior engineer would repeat at the start of every session. Claude Code reads `CLAUDE.md` as context, not as a guarantee. Hooks and deny rules are the part that runs whether or not the model complies.

The layout follows Anthropic's current Claude Code docs: [memory](https://code.claude.com/docs/en/memory), [skills](https://code.claude.com/docs/en/skills), [sub-agents](https://code.claude.com/docs/en/sub-agents), [hooks](https://code.claude.com/docs/en/hooks), [settings](https://code.claude.com/docs/en/settings), [permissions](https://code.claude.com/docs/en/permissions), [headless](https://code.claude.com/docs/en/headless), and [GitHub Actions](https://code.claude.com/docs/en/github-actions). The working style follows [Best practices for agentic coding](https://www.anthropic.com/research/claude-code-best-practices), [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), and [Effective harnesses for long-running agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents).

Nothing in this decision changes ingestion, the warehouse, Terraform resources, or the dashboards.

## Decision

- `CLAUDE.md` at the root is the short project brief. It imports the ADR index with `@docs/adr/README.md` and names runbooks instead of inlining them. `CLAUDE.local.md` is gitignored. Nested `CLAUDE.md` files cover dbt, Terraform, and Airflow, which do not share one command set.
- `.claude/settings.json` is the shared settings file. Its allow list is the Makefile targets and the exact `terraform fmt` / `init -backend=false` / `validate` commands those targets run. Its deny list blocks `terraform apply`, `terraform destroy`, `aws`, force-push, `rm -rf`, and reads of `.env` and `secrets/`.
- `.claude/hooks/` holds two command hooks. `PostToolUse` on `Edit|Write` formats the file that changed. `PreToolUse` on `Bash` exits 2 when the command would apply or destroy Terraform, call a mutating AWS CLI, force-push, or `rm -rf`. Both read the hook JSON from stdin.
- `.claude/skills/` holds the repeated workflows: new slice, new Olinda entity, dbt model, verify, and release. `.claude/agents/` holds two read-only reviewers, each limited to Read, Grep, and Glob.
- Long-running work uses `docs/agentic/feature_list.json`, `docs/agentic/progress.md`, and `scripts/agent-init.sh`. Features start failing. An agent marks `passes` only after the listed steps succeed, and does not delete features.
- `.github/workflows/claude.yml` runs `anthropics/claude-code-action@v1` when a comment or new issue mentions `@claude`. The job checks `ANTHROPIC_API_KEY` and skips the action when the secret is empty, so a missing key is not a failed run. The workflow is not part of the required CI jobs in `.github/workflows/ci.yml`.

Headless use is `claude -p`, documented on the headless page. This repository does not invoke it from CI.

## Alternatives considered

- Put the runbooks and the Olinda spike inside `CLAUDE.md`. That blows the context window on every session. The context-engineering note is to keep the always-loaded file small and read the long note when the task needs it.
- Rely on `CLAUDE.md` alone to forbid `terraform apply`. A model can skip a paragraph. The deny rule and the exit-2 hook do not depend on that.
- Add sqlfluff in the format hook. The project does not depend on sqlfluff. Ruff and `terraform fmt` are the formatters that already exist.
- Run the Claude Code GitHub Action on every pull request. That spends API tokens and fails closed when the secret is absent. Mention-triggered, and skipped without a key, matches a public portfolio.

## Consequences

- A clone has the team settings as soon as it is trusted. Deny rules apply before that trust step. Allow rules wait for trust, which is Claude Code's documented behavior.
- `scripts/agent-init.sh` may create `.venv` and install `.[dev]`. It does not start AWS, and it does not run `terraform apply`.
- The GitHub Action still needs the Claude GitHub App installed on the repository, and a repository secret named `ANTHROPIC_API_KEY`, before `@claude` does any work. Until then the workflow succeeds and skips.
- Hook tests live under `tests/` and run with `make test`, which CI already calls.
